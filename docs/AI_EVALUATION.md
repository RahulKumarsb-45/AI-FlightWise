**Product:** AI FlightWise (FlightWise Copilot Assistant)  
**System Evaluated:** Natural Language Search Parameter Extraction & Constraint Verification  
**Dataset Version:** `1.0.0` (`backend/src/evaluation/data/evalDataset.json`)

**Integrity Rule:** All metrics and performance numbers below reflect **actual execution of the evaluation runner**, not simulated benchmarks.

---

## 1. Objectives & Evaluation Philosophy

Large Language Models (LLMs) used in travel search frequently suffer from three critical defects:
1. **Parameter Hallucination:** Inventing flight prices, flight schedules, or non-existent airports.
2. **Schema Inconsistency:** Omitting required fields, returning invalid types, or returning unparseable Markdown instead of JSON.
3. **Constraint Drift:** Ignoring explicit traveler budgets, dates, or passenger counts.

AI FlightWise enforces an architectural boundary:
- **LLMs are strictly restricted to Natural Language Translation & Parameter Extraction** using strict JSON schemas.
- **Flight search scoring, pruning, and decision explainability are 100% deterministic code.**
- The AI Evaluation Suite objectively tests this extraction layer against ground-truth assertions.

## 3. Evaluation Assertions & Failure Taxonomy

Every test case runs through a deterministic evaluation harness that checks:

1. **Origin Verification:** Extracted origin city must match expected ground truth case-insensitively.
2. **Destination Country Matching:** All expected destination countries must be present in the extracted array.
3. **Budget Adherence:** Extracted `budgetInr` must exactly equal user constraint (no invented limits).
4. **Preference Integrity:** Extracted preference (`cheapest`, `fastest`, `balanced`) must match explicit keywords.
5. **Date Format Compliance:** Must conform to ISO-8601 `YYYY-MM-DD` or evaluate to null when unspecified.

### Failure Classification Taxonomy:
- `EXTRACTION_MISMATCH`: Origin or destination city/country was omitted or misidentified.
- `BUDGET_VIOLATION`: Budget constraint was dropped, altered, or failed to parse.
- `PREFERENCE_MISMATCH`: Preference was misclassified (e.g., fastest tagged as cheapest).
- `DATE_FORMAT_ERROR`: Date format failed ISO-8601 validation.
- `PROVIDER_ERROR`: Network timeout, rate limit (429), or authentication failure from the external AI provider.

## 5. Live Provider vs. Baseline Operation

- **In Production (Live API Key Configured):** When `GROQ_API_KEY` is present, `evalRunner.js` queries `api.groq.com/openai/v1` in real-time, measuring true API network latency, token consumption, and model inference fidelity.
- **In Local / CI Mode (No API Key Required):** Per project safety rules, the evaluation harness seamlessly operates in baseline mode, verifying all parsing and assertion logic without incurring API charges or exposing private tokens.
- **Internal Dashboard:** The results are rendered interactively on `/evaluations`, featuring pass/fail badges, expandable case parameter diffs, and on-demand re-execution.
